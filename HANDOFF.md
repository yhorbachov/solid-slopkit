## How the maintainer works

- One roadmap step per request, named by ID ("go ahead with M1.30"). Never start the next step on your own.
- After a step: report what was built, decisions with their reasons, anything found or left open, then **ask before committing**. Commit only when told. ## What every step contains (the pattern to copy)

For component `foo` in folder `<group>` (`layout`, `button`, `data-display`, `feedback`, `inputs`, `surfaces`, `typography`, `provider`):

1. `packages/ui/src/components/<group>/foo/`: `foo.tsx`, `foo.module.css`, `foo.md` (the LLM reference), `foo.test.tsx` (jsdom), `foo.browser.test.tsx` (Chromium, when there's layout, color or keyboard to check), `foo.fixtures.tsx` (SSR scenarios), `index.ts`.
2. Export from `components/<group>/index.ts` (alphabetical).
3. Docs: `apps/docs/src/routes/ui/foo.tsx`, examples in `apps/docs/src/examples/foo/*.tsx` (imported twice, as the component and as `?raw`), a nav entry in `apps/docs/src/nav.ts` (alphabetical within the group), a link in `packages/ui/src/llms.md`.
4. Roadmap: tick the box and add the component to the "Done" list at the top.
5. `apps/docs/file-routes.d.ts` is regenerated by the running dev server; its diff is expected.

Good recent models: Alert (`feedback/alert`), Table (`data-display/table`, a component with parts), Progress and RingProgress (custom properties set inline), Notification (optional JSX props done right).

Conventions that recur:

- Root class `.slp-foo` plus the CSS module class via `joinClass(['slp-foo', style.foo], props.class)`; slots are `data-slot="foo-part"`; state and variants are `data-*` attributes; public custom properties (`--slp-foo-color`, `--slp-foo-content`) only where one value feeds several declarations; internal ones are `--_foo-*`. All rules inside `@layer slopkit.components`. Colors only from tokens (`color-mix` with `transparent`, `white` or `black` is fine).
- Color roles: one `&[data-color='<role>']` block per role setting `--_foo-theme-color` (and `-content`), resolved through `var(--slp-foo-color, var(--_foo-theme-color))`.
- Values that can be anything (a URL, a number of px, a fraction) go into an internal custom property merged into the `style` object with a memo (see Text, BackgroundImage, Progress). Don't invent data-attribute selectors for them.
- Built-in strings (accessible names) are props with English defaults: Loader's `label = 'Loading'`, Progress's `label = 'Progress'`.
- `mergeDefaultProps` treats an explicit `undefined` as a value: passing `color={props.color}` down to a component overrides its default. Pass `props.color ?? '<default>'`.
- Solid 2 JSX types use lowercase attribute names: `tabindex`, not `tabIndex`. Enumerated ARIA attributes take strings: `aria-pressed={on ? 'true' : 'false'}`; a boolean `false` removes it, and lint catches it.
- An element chosen by a prop (`ordered`, `block`) is read once with `untrack`, like `as`; say so in the reference.
- Lists render with `<For>`, never `Array#map` (lint rule).
- Scrollable regions (`Code` block, `Table.ScrollContainer`) get `tabindex={0}` by default: browsers in the baseline don't all let the keyboard reach a scroller.

## Pitfalls hit this session (don't repeat them)

1. **Optional JSX props and hydration.** A JSX prop is a getter that creates its elements when read. If a component reads one eagerly (`createMemo(() => props.icon)` at setup) but doesn't render it in some state (loading, disabled), the server builds it without emitting it, and the client, while hydrating, looks for it in the page: "Hydration Mismatch", then REACTIVITY_HALTED for the whole page. Read such props only where they're rendered, inside the branch or an inner component (Indicator's `IndicatorMark`), and decide "is it passed" with `untrack(() => 'icon' in props)`. Every SSR fixture should cover each state in which an optional JSX prop is hidden.
2. **Checking the browser console.** The `pattern` filter of the console tool is a plain substring: `"hydrat|Error"` matches nothing and looks like a clean console. Read with `onlyErrors: true` and no pattern. The log accumulates per origin, so read the count ("last 1 of N") before and after loading a page. Also click an interactive example: a halted page still renders its server HTML.
3. **Node version.** The shell's default `node` (mise 22.17) is below the repo's `engines`, and `pnpm lint` fails to load `oxlint.config.ts`. Prefix commands with `export PATH=~/.local/share/mise/installs/node/24.20.0/bin:$PATH;`.
4. **Flaky full runs under load.** When the machine is busy (load average ~18 from another session), a few random SSR hydration tests time out. They pass alone. Run the full suite with `npx vitest run --maxWorkers=4`.
5. **CSS modules hash `@keyframes` names.** Assert animation names with `toMatch(/slp-foo-spin/)`, not `toBe`.
6. **`animation` shorthand resets `animation-delay`.** Put per-part delays after the rule that sets the animation (Loader dots).
7. **Floating point in percentages.** Compute `(value * 100) / max`, not `value / max * 100` (55 gave `55.00000000000001%`).
8. **`For keyed={false}`** re-running its own memo is counted as waste by `toHaveNoWaste()`; Highlight documents why it asserts a re-run budget instead. Before dropping the waste check, find the wasted scope (dump `artifact.attribution.reruns`) and restructure first: Notification's waste went away with one memo and a `Switch`.
9. **A positioned `::before` paints over in-flow text.** For a layer under the children, give the root `isolation: isolate` and the layer `z-index: -1` (ColorSwatch, the Notification ping).
10. **An `aria-label` on a role-less `span`** is prohibited ARIA (axe fails). Give it `role="img"` or put the name in the text.
11. **Docs router types.** At ~44 pages, inferring the router from the generated route tuple hit TS2589; `apps/docs/src/router.ts` now widens `pageRoutes` to an array. Don't undo it.
12. **Events in jsdom tests need `flush()`** before asserting on state they change (`fireEvent.click(...)`, then `flush()`).
13. **Script against the docs page only after hydration.** A click sent right after `navigate` is replayed after hydration, so reads look one step behind; wait about a second first. With the browser pane hidden, screenshots and real clicks fail and CSS transitions don't advance: verify through the DOM.

## Verifying in the browser

- The docs dev server on port 3100 usually belongs to another session; the browser tools reach it, but you can't restart it, and its server-side modules can go stale. The `PostToolUse` hook warns about this.
- When you need a fresh server: add a temporary entry to `.claude/launch.json` (it's tracked) on another port, e.g. `"docs-verify"` on 3101 with `--port 3101 --strictPort`, start it with `preview_start`, and afterwards `preview_stop` it and restore the file exactly (back it up to the scratchpad first).
- Check each page in light and dark: the "Toggle color scheme" button (find it with `find`; screenshot coordinates drift). Leave the scheme as you found it.
- The SSR test helper (`packages/ui/test/ssr.tsx`, `expectHydration`) can't resolve `@lucide/solid` from `packages/ui`. To reproduce with a real icon, import its source file from `node_modules/.pnpm/@lucide+solid@.../dist/source/icons/<name>.jsx` in a scratch fixture.
